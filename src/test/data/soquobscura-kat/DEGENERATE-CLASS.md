# The degenerate-witness reject class

**Added 2026-08-17.** Extension to the frozen 64-vector corpus. The core three files
(`range.jsonl`, `balance.jsonl`, `ve.jsonl`) and their `sha256` pins are **unchanged** — this
class lives under `extension_files` in `manifest.json` precisely so the `== 64` assertion in
`soquobscura_kat_corpus_tests.cpp` keeps its meaning.

## Why it exists

The frozen 64 contain **24 reject vectors and not one is a degenerate witness.** Enumerated,
they cover the L2 norm bound, non-binary digits, tamper/bitflip/truncation, balance
arithmetic, and VE wrong-value/cross-key. The `*-ok-zero` vectors are zero-**value** accepts,
which is a legitimate thing to prove and is not the same thing at all.

So the core corpus was structurally blind to the one bug class this repository has shipped
**twice**:

| where | status |
|---|---|
| LatticeFold+ `EvalCheckFoldProof` | Halborn 7.3, CRITICAL 10.0, six remediations, signed off **SOLVED**, still exploitable |
| `LatticeRangeProofV2` | wire-reachable from public data with a 12,321-byte blob |

In both, every accept-path check is **homogeneous in the witness**, so an all-zero witness
satisfies all of them, and the only non-homogeneous check is a Fiat-Shamir seed the attacker
reads off public data and plants.

And the core corpus could never have exposed it: `manifest.lazer_commit` records that its
expected verdicts were generated **by LaZer**, so any defect LaZer shares would have been
written down as ground truth.

## Provenance

Generated by `contrib/degen-corpus-gen.c` **through LaZer's own encoder**
(`lnp_tbox_encproof`), so every vector **decodes cleanly** and therefore reaches the soundness
path rather than dying in the decoder.

⚠️ That distinction is not academic. An earlier byte-level probe rejected 90/90 mutants and
looked like strong evidence. Instrumenting the reject sites showed **every single one died at
`DECPROOF`** — none ever reached `poly_eq(c, c2)`. The probe had no soundness content
whatsoever. These vectors exist because of that lesson.

Every vector was verified to be **rejected** before being written; the generator fails loudly
on an accept, because an accepted degenerate witness is a forgery, not a test case.

## The three modes, and why the third is the one that matters

| suffix | witness | wire-reachable | rejected at |
|---|---|---|---|
| `-degen-zero` | all prover fields zeroed | ✅ under cap | `CHALLENGE_POLY_EQ` |
| `-degen-doubled` | all fields doubled | ⛔ **over cap** | `Z34_NORM` |
| `-degen-minnonzero` | all zeroed except one `z1` coefficient = 1 | ✅ under cap | `CHALLENGE_POLY_EQ` |

- `-degen-zero` is wire-reachable but a *"reject if the witness is all zeros"* patch would
  fake it.
- `-degen-doubled` is non-zero but **exceeds the per-relation cap** in `soq_lbpp_wire.h`
  (range 22496, balance 25140, ve 30930), so `soq_lbpp_unwrap_proof` kills it with
  `ERR_OVERSIZE` before the verifier ever runs. Keep it as a verifier-level test; it is not a
  wire test.
- **`-degen-minnonzero` is the member the grading contract requires**: non-zero *and* under
  the cap, so it is genuinely reachable and no all-zeros shortcut can fake it.

## Why LaZer rejects them, i.e. what a port must not break

`lnp-quad.c:455-478`. The evaluation term

```
v = z*R2*z + c*r1*z + c^2*r0 - f          (f = c^2*t - bextprime*z21)
```

is **absorbed into the challenge derivation**, not compared against zero:

```
cseed = SHAKE128(hash || enc(t, v, w1))
c2    = poly_urandom_autostable(omega, log2omega, cseed)
if (!poly_eq (c, c2)) reject;
```

So the equation check **is** the Fiat-Shamir check. With a zero witness `v = c^2*r0`, so a
forger needs `c = F(H(… c^2*r0 …))`: a **hash fixed point**. Chasing that fixed point for 64
iterations per vector never converged.

⛔ Every norm check in that function is homogeneous — `l2sqr(z1) <= bnd`,
`l2sqr(gamma*w1) <= Bsqr`, `linf(h) <= m` — and a zero witness passes all three. Soundness
rests on `poly_eq(c, c2)` **alone**, plus `poly_urandom_autostable` emitting fixed-weight ω
challenges so the zero polynomial is outside its image.

**A port or extraction must preserve, verbatim:** (a) `v` absorbed into `cseed` rather than
compared to zero, (b) `poly_eq(c, c2)`, (c) the fixed-weight constraint. "Simplifying" (a)
into a separate `v == expected` comparison reintroduces the forgery.

## Status

⚠️ These vectors are **pinned, not executed**, for the same reason the core gate is not: there
is deliberately no consensus verifier in-tree yet. The value is that the class is frozen and
provenance-recorded *before* a verifier exists, so it cannot be quietly regenerated to make
that verifier pass. It becomes executable the moment one lands.
